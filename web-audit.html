A web audit with a reference build

Practice Software Testing publishes its Toolshop twice: clean, and with bugs planted by its authors. One suite of 43 tests runs on both. A defect counts only when its check fails on the bug build and passes on the clean one.

How it works

Two projects, one suite

Each test runs as project bugs and project clean. Only the addresses differ. 

projects: [
  { name: 'bugs',  use: { buildName: 'bugs' } },
  { name: 'clean', use: { buildName: 'clean' } },
]

Pin the defect

knownBug(id) knows which builds have the defect and calls test.fail() there. Everywhere else the same assertion must pass. When the authors fix it, the run turns red. 

knownBug('WQA-3');
const prices = await shop.prices();
expect(prices).toEqual(
  [...prices].sort((a, b) => a - b));

Check properties, not data

The site is shared and its data changes all day. Checks assert order, matching and structure: the list equals itself sorted, every result mentions the term, each label belongs to its own field.

Get past the bot check politely

Cloudflare stops headless browsers and challenges reloads. Tests run headed Chrome in xvfb, load the shop once and then move inside the Angular app like a user. One worker, no writes, a weekly run.
